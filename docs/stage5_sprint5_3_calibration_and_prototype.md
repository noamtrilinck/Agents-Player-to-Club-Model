## Style-vs-Level context audit (traced against actual NTS build code, not planning docs)

This was requested before any formula work, to establish the exact boundary between Stage 5
(style) and Stage 6 (level), and to check for accidental double-counting.

### A documentation correction discovered during this trace

Stage 3's own documentation (`docs/stage3_player_evaluation_integration.md` §4 decision 3, and
`production/player_evaluation_integration/feature_manifest.py`'s `context_ability` comment)
stated that Context Ability is "already blended into every CORE `*_final` value at NTS's locked
20% weight." **Traced directly against NTS's actual build code, this is factually imprecise —
corrected in both files as part of this sprint** (comment/rationale text only; no computation,
methodology, or locked Stage 3 output changed):

- `production/competitive_context/build_attacking_architecture.py` /
  `build_defensive_architecture.py`: each individual CORE Ability's own `score_context_adjusted`
  (the exact source column Stage 3's `<dim>_final` reads) = `score_raw + OwnDominance-only
  nudge`. **Verified numerically**: raw-vs-adjusted correlation 0.9999, mean|Δ|≈0.06 across the
  real population (Crossing checked directly) — Context Ability plays **no material role** here.
- `production/competitive_context/build_philosophy_and_defensive_scores.py`
  (`CONTEXT_WEIGHT = 0.20`): the 20% Context Ability blend is applied **only** to the 3 attacking
  Philosophy scores and the Final Defensive Score — all SUPPORTING, never CORE. **Verified
  numerically**: raw-vs-adjusted correlation 0.82, mean|Δ|≈5.8 (Control Attacking Score checked
  directly) — a real, substantial blend, but at a layer Stage 3 already excludes from CORE.

The underlying **decision** (exclude Context Ability from CORE) was and remains correct; only
the **stated mechanism** was wrong. This doesn't change anything Stage 4 or Stage 5 consumes —
it just makes the audit trail accurate.

### 1. What level/context information is embedded in the 11 CORE Ability T-scores

- **GlobalClubStrength_v3 / OpponentQuality_v3 / Context Ability**: confirmed **not** embedded
  (see above).
- **OwnDominance** (a club's domestic-league dominance, separate from Context Ability): **yes,
  a small, explicit, evidence-calibrated nudge** is embedded directly in each CORE Ability's own
  `_final` value (transfer-pair-regression-fit, family-pooled slope −0.31, not significant
  almost everywhere; Ball Carrying/Dribbling is the one Ability with a real, significant effect,
  slope −2.48, p=0.011). Small in magnitude by design.
- **An implicit, uncorrected residual league-level signal**: NTS's T-score standardization
  (`restandardize_to_tscore`) is computed **per position group, pooling ALL leagues together**
  (confirmed — no league-level `groupby` anywhere in the per-Ability build scripts). Nothing
  explicitly removes a systematic league effect from the underlying box-score-derived component
  before this pooled standardization. **Measured directly on the real Stage 3 population**:
  mean CORE-dimension level varies by league from 49.30 (Ekstraklasa) to 51.65 (Virsliga) — a
  **2.35-point spread**, small (roughly a quarter of one population SD) but real and
  **not the direction naive intuition would predict** (weaker leagues read slightly *higher* on
  average, not lower — plausibly a homogeneity/measurement artifact of pooled z-scoring rather
  than genuine ability inflation, but not further diagnosed here — out of scope for a Stage 5
  sprint to redesign Stage 3's normalization).

### 2. What's embedded in OBSERVED profiles

Nothing beyond what's embedded in the 11 CORE Abilities above — an OBSERVED profile is
literally a minutes-weighted mean of those same CORE Ability values (confirmed in Sprint 5.2
Part A). No separate club/league-strength signal is added at this layer.

### 3. What's embedded in SYSTEM-COMPATIBLE (predicted) profiles

Purely Team Environment (47 engineered team-season style metrics — possession, passing,
pressing, shooting patterns, etc.), confirmed independent of GlobalClubStrength/Context Ability
(Sprint 4.1's own audit: "a rich, currently-unused team-style feature library... separate from
the Context Ability layer"). Team Environment numbers will naturally *correlate* with league
quality in the real world (elite-league teams tend to have different passing/pressing profiles
than lower-league teams) — but that's genuine **style** information the Ridge model is supposed
to learn from, not a smuggled-in level score. No club-strength/market-value feature is a Ridge
input.

### 4. What Stage 6 must avoid double-counting

Stage 6 (Level & Opportunity) is free to use Context Ability / GlobalClubStrength / league
strength directly — Stage 3 already kept these as SUPPORTING specifically for this purpose, and
this audit confirms they are **not** embedded in the CORE dimensions Stage 5 consumes. No hard
double-count exists between an explicit Stage 5 signal and an explicit Stage 6 signal. Stage 6
should be aware, though, that a **small, residual, uncorrected league-level effect (≈2.35 T-score
points)** already exists inside the CORE Ability T-scores Stage 5 uses (from pooled-league
normalization, not from any Stage 6-relevant score) — soft, unavoidable background noise, not
something to "fix" at either stage.

### 5. Does anything discovered require reconsidering the Stage 5 formula?

**No.** The residual league effect (§1) is small and, critically, **symmetric across both sides
of every Style Fit comparison** — a player's CORE dims and a Club×Position profile's CORE dims
(OBSERVED = literal mean of the same CORE dims; SYSTEM-COMPATIBLE = trained against the same
CORE-dim targets) carry the same underlying scale and the same class of residual noise, so a
same-scale distance metric (MAD) is not meaningfully biased by it. No change to the locked
Sprint 5.2 methodology is warranted from this audit.

## Part A — Research-only asymmetric MAD (implemented)

`asymmetric_mad_matrix(Pv, Cv, ratio)` in the research script: for every shared (non-missing on
both sides) CORE dimension, `diff = player − profile`; `deficit = max(0, −diff)`,
`surplus = max(0, diff)`; per-pair distance = `mean(ratio × deficit + surplus)` over the
dimensions actually used. `ratio = 1.0` reduces exactly to symmetric MAD (verified — Sprint
5.2's pooled mean of 6.30 at ratio 1.0 matches this script's own ratio=1.0 output). Missing-data
policy respected throughout: only mutually-available dimensions counted, `n_dims_used` computed
per pair, no imputation anywhere.

## Part B — Ratio calibration (population-level)

Tested ratios: 1.00 (baseline), 1.25, 1.50, 1.75, 2.00, across all 3,823,104 valid player×club
pairs (same population as Sprint 5.2).

| Ratio | Pooled mean | Pooled median |
|---|---|---|
| 1.00 | 6.30 | 6.01 |
| 1.25 | 7.09 | 6.77 |
| 1.50 | 7.87 | 7.51 |
| 1.75 | 8.65 | 8.23 |
| 2.00 | 9.44 | 8.95 |

Scores scale up roughly linearly with the ratio (expected — most pairs have *some* deficit
dimensions, so a larger multiplier raises the average distance). More importantly, **the choice
of ratio has real practical consequences, not just cosmetic scaling**: sampling 40 players per
position (440 total) and checking whether their single *best-fit candidate club* changes between
ratio 1.0 and ratio 2.0 — **45%–65% of sampled players' best-fit club changes** depending on
position (pooled ≈56%). This is not a parameter that can be picked casually; it materially
changes recommendations.

## Part C — Leakage-safe leave-one-out validation

**Methodology**: for every Club×Position combination with ≥2 contributing players
(`observed_club_position_profiles.csv`'s `n_contributing_players ≥ 2`), each contributor is
individually left out, the OBSERVED profile is **reconstructed from the remaining
contributors' own minutes-weighted mean only**, and the left-out player is then ranked (by
asymmetric MAD, per ratio) against that reconstructed profile **and** every *other*
evidence-bearing club's real, unmodified OBSERVED profile at the same position. This tests
whether each ratio recovers a plausible true relationship without any leakage from the player's
own data into the profile being validated against.

**Coverage**: 5,343 contributors sit in multi-player evidence combos and are LOO-testable; 1,900
contributors are the sole contributor at their Club×Position and are correctly excluded (cannot
reconstruct a profile from zero remaining evidence). **All 5,343 eligible instances were used —
100% of usable evidence.**

**Results** (percentile = how well the true, reconstructed home club ranks among all candidate
clubs; higher is better; 1.0 = best possible):

| Ratio | Mean percentile | Median percentile | Top-10% recovery | Top-25% recovery | Mean rank |
|---|---|---|---|---|---|
| 1.00 | 0.542 | 0.554 | 15.5% | 32.8% | 207.9 |
| 1.25 | 0.540 | 0.553 | 15.8% | 32.4% | 209.0 |
| 1.50 | 0.537 | 0.547 | 15.6% | 31.8% | 210.2 |
| 1.75 | 0.535 | 0.549 | 15.3% | 31.5% | 211.4 |
| 2.00 | 0.533 | 0.548 | 15.2% | 31.6% | 212.4 |

**Honest, non-intuitive finding**: recovery of the true relationship **degrades slightly and
monotonically as the ratio increases** — symmetric MAD (1.0) is the best pure recoverer among
everything tested, and every asymmetric ratio trades away a small amount of recovery accuracy.
The degradation is modest (mean percentile drops from 0.542 to 0.533 across the full tested
range — about 1.7% relative) but it is consistent and real, not noise. This makes sense on
reflection: a leave-one-out validation checks whether teammates predict each other well, and
teammates' natural within-position variance produces roughly balanced small deficits and
surpluses around each other — amplifying deficits disproportionately doesn't help recover *that
specific* relationship, even though it may still be the right choice for the separate,
independent football argument that a real shortfall should matter more than a real surplus for
recommendation purposes.

## Part E — Conditional Alternative Opportunity (exploratory, not built)

Pattern investigated: player has **low/moderate OBSERVED similarity** to a club's actual
positional archetype **but strong SYSTEM Fit** to what that club's environment predicts it needs
— a genuinely different-looking recommendation from the usual "similar to who plays there now."

**Threshold sensitivity** (position-relative percentiles, ratio=1.5, self-club excluded):

| Threshold pair | Definition | Players qualifying (≥1 club) | % of population | Qualifying pairs |
|---|---|---|---|---|
| p60 / p20 | loose | 3,772 | 50.5% | 67,330 |
| p70 / p15 | moderate | 2,706 | 36.2% | 26,129 |
| p80 / p10 | strict | 1,521 | 20.4% | 7,427 |
| p90 / p5 | very strict | 547 | 7.3% | 1,099 |

**The loose definition qualifies over half the population — clear evidence it's far too
permissive to serve as a rare, conditional signal** (directly contradicting the intended "most
players should have none" behavior). Even the "strict" tier (p80/p10) still touches a fifth of
all players. Only the **very strict tier (p90/p5) — 7.3% of players, one qualifying club each on
average** — starts to look like a genuinely selective, conditional signal rather than something
that fires for half the population.

**Manually inspected very-strict examples** (all Attacking Midfield in this sample — worth
noting, not yet explained): e.g. Sam Larsson at Debrecen (observed distance 17.6, system
distance 3.1 — a striking gap), Mounir El Allouchi at FC Utrecht (14.8 vs. 4.0), Enis Bardhi at
Club Brugge (15.4 vs. 3.7). These are football-plausible on their face (technically progressive,
creative players being flagged as system-compatible with clubs whose incumbent AM archetype
looks nothing like them) but were not verified against real transfer/scouting outcomes — this
sprint had no such ground truth available.

**Recommendation for a future sprint**: something in the p85–p90 / p5–p10 range looks like the
right order of magnitude for a genuinely conditional signal, but the exact cutoff is a football
judgment call this sprint cannot make unilaterally — flagged in Decisions §, below.

| Quadrant | Count | Share |
|---|---|---|

## Part G — Multiple-archetype diagnostics under asymmetric MAD

Repeating Sprint 5.2's Part E analysis with asymmetric MAD (ratio 1.5) instead of symmetric MAD,
across all 255 qualifying two-profile cases:

- **Profile A wins for 49.1% of realistic candidates on average; Profile B wins for 50.9%** —
  essentially unchanged from the symmetric-MAD result (51.4% B in Sprint 5.2) — confirms
  best-fit-to-either continues to behave sensibly and is not an artifact of the specific distance
  metric.
- 17.6% of (player, club) evaluations are "close calls" (A and B within 1 MAD point) — genuinely
  near-ties where either archetype is a reasonable claim, not a coin-flip that should be hidden.
- Mean improvement from best-of-two vs. A-only: **1.84 points** (mean_A_only 10.19 vs.
  mean_best_of_two 8.35) — a real, non-trivial average benefit from considering both archetypes,
  consistent with (slightly larger than) Sprint 5.2's symmetric-MAD finding.
- Most-A-favoring cases (e.g. Bryne Centre Forward, 97.9% of candidates prefer A) and
  most-B-favoring cases (e.g. Koninklijke Lierse Sportkring Right Back, 99.0% prefer B) exist at
  the extremes — confirming the split isn't uniformly ~50/50 everywhere, it varies genuinely by
  case, which is exactly what "two distinguishable archetypes" should look like.

## Part H — Score-calibration exploration (no formula locked)

Pooled asymmetric-MAD (ratio 1.5) distribution, for reference:

| Percentile | Value |
|---|---|
| p1 | 3.50 |
| p5 | 4.46 |
| p10 | 5.04 |
| p25 | 6.11 |
| p50 (median) | 7.50 |
| p75 | 9.26 |
| p90 | 11.18 |
| p95 | 12.49 |
| p99 | 15.26 |

**Two calibration approaches considered, neither adopted**:

1. **Percentile-based mapping**: map a raw MAD/asymmetric-MAD value to "what fraction of all
   real player-club pairs are at least this good" (i.e. a population-relative percentile,
   inverted so lower distance → higher score). Advantage: automatically well-calibrated to the
   actual data distribution above, no arbitrary anchor points; a "90/100" score would mean
   "better fit than 90% of all real pairs," a defensible, explainable claim. Disadvantage:
   the meaning of a given percentile could drift if the underlying population changes (new
   season, more clubs) — would need periodic recalibration, which is fine but should be an
   explicit, documented process, not silent drift.
2. **Fixed-anchor sigmoid/exponential-decay mapping**: pick 2–3 anchor points (e.g. "MAD=4 → 90",
   "MAD=8 → 50 [near-median]", "MAD=14 → 10") and fit a smooth monotonic curve through them.
   Advantage: stable over time, doesn't silently redefine "good" as the population shifts.
   Disadvantage: the anchor points themselves are inherently a **subjective choice** — exactly
   the kind of decision you asked to review before locking, not something this sprint should
   pick unilaterally.

**Recommendation**: option 1 (percentile-based) requires no subjective anchor and is directly
defensible from the empirical distribution already produced here — lean toward it, but this is
presented as a recommendation requiring your sign-off (see Decisions §), not a locked choice.
**The raw asymmetric-MAD value must remain available internally regardless of which
user-facing calibration is eventually chosen** — this sprint's prototype functions already keep
it as a first-class field, never discarded in favor of a display score.

## Recommended deficit/surplus ratio and why

**Recommendation: 1.25**, presented as a genuine trade-off, not a clean winner:

- Pure leave-one-out recovery (Part C) shows symmetric MAD (1.0) as the single best performer,
  with every tested asymmetric ratio costing a small, monotonically increasing amount of
  recovery accuracy.
- Since Sprint 5.2 already locked asymmetric treatment as a framework (deficits must matter more
  than surpluses — a football-conceptual decision independent of this recovery metric), the
  right empirical question becomes "which tested asymmetric ratio costs the *least* recovery
  accuracy while still being meaningfully asymmetric" — that is **1.25** (mean percentile 0.540,
  essentially indistinguishable from 1.0's 0.542; top-10% recovery 15.8%, actually the *highest*
  of any ratio tested including symmetric).
- 1.75 and 2.00 show larger, though still modest, recovery costs (0.535 and 0.533 mean
  percentile) for more aggressive deficit weighting.
- This is **not presented as a definitive optimum** — the differences between all five tested
  ratios are small in absolute terms, and 1.25 is a reasoned pick from the tested range, not a
  proven-best value from a continuous search. Flagged for your approval below.
